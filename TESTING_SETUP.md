# Testing Setup with Mockery

This project uses **mockery** to automatically generate mocks for interfaces, replacing manual mock implementations.

## What is Mockery?

Mockery is a tool that automatically generates mocks from Go interfaces. It provides:
- **Type-safe mocks** generated from interfaces
- **Expectation API** for flexible mock behavior configuration
- **Automatic verification** of mock expectations
- **Clean, readable test code** without manual mock implementations

## Installation & Setup

### 1. Install Mockery

```bash
go install github.com/vektra/mockery/v2@latest
```

### 2. Generate Mocks

Generate all mocks using the Makefile:

```bash
make mocks
```

Or manually:

```bash
mockery --all --output=internal/usecase/mocks --outpkg=mocks --case=underscore
mockery --output=internal/repository/mocks --outpkg=mocks --case=underscore -r internal/repository
```

This creates:
- `internal/usecase/mocks/MockProductUseCase.go` - Mock for ProductUseCase interface
- `internal/repository/mocks/MockProductRepository.go` - Mock for ProductRepository interface

### 3. Run Tests

```bash
go test -v ./...
```

## Using Mockery in Tests

### Creating a Mock

```go
import "project-test-primo/internal/usecase/mocks"

func TestExample(t *testing.T) {
    // Create a new mock
    mockUC := mocks.NewProductUseCase(t)
    
    // ...
}
```

### Setting Expectations

```go
// Basic expectation
mockUC.EXPECT().
    CreateProduct(mock.Anything, mock.Anything).
    Return(product, nil).
    Once()

// With matchers
mockUC.EXPECT().
    CreateProduct(mock.Anything, mock.MatchedBy(func(r *domain.CreateProductRequest) bool {
        return r.Name == "Test" && r.Price > 0
    })).
    Return(product, nil).
    Once()

// Multiple calls
mockUC.EXPECT().
    GetProduct(mock.Anything, int64(1)).
    Return(product, nil).
    Times(3)

// Any number of calls
mockUC.EXPECT().
    GetProduct(mock.Anything, mock.Anything).
    Return(product, nil).
    Maybe()
```

### Verifying Expectations

Mockery automatically verifies expectations when the test ends. No need to manually assert:

```go
func TestCreateProduct(t *testing.T) {
    mockRepo := mocks.NewProductRepository(t)
    
    mockRepo.EXPECT().
        Create(mock.Anything, mock.Anything).
        Return(product, nil).
        Once()
    
    uc := NewProductUseCase(mockRepo)
    uc.CreateProduct(context.Background(), req)
    
    // Automatically verifies that Create was called exactly once
}
```

## Common Matchers

### Exact Matching
```go
mockUC.EXPECT().
    GetProduct(mock.Anything, int64(1)).
    Return(product, nil)
```

### Flexible Matching
```go
// Match anything
mockUC.EXPECT().
    GetProduct(mock.Anything, mock.Anything).
    Return(product, nil)

// Custom matcher
mockUC.EXPECT().
    CreateProduct(mock.Anything, mock.MatchedBy(func(r *domain.CreateProductRequest) bool {
        return r.Name != "" && r.Price > 0
    })).
    Return(product, nil)
```

## Test Organization

### Handler Tests (`internal/handler/product_test.go`)

```go
func TestProductHandler_CreateProduct(t *testing.T) {
    t.Run("successful creation", func(t *testing.T) {
        // Arrange
        mockUC := mocks.NewProductUseCase(t)
        mockUC.EXPECT().
            CreateProduct(mock.Anything, mock.Anything).
            Return(expectedProduct, nil).
            Once()
        
        // Act
        handler := NewProductHandler(mockUC)
        w := makeRequest(handler, ...)
        
        // Assert
        assert.Equal(t, http.StatusOK, w.Code)
    })
}
```

**Tests handler layer:**
- HTTP request parsing
- Response formatting
- Error handling at HTTP level
- Uses mocked UseCase

### UseCase Tests (`internal/usecase/product_test.go`)

```go
func TestProductUseCase_CreateProduct(t *testing.T) {
    t.Run("successful creation", func(t *testing.T) {
        // Arrange
        mockRepo := mocks.NewProductRepository(t)
        mockRepo.EXPECT().
            Create(mock.Anything, mock.Anything).
            Return(expectedProduct, nil).
            Once()
        
        // Act
        uc := NewProductUseCase(mockRepo)
        product, err := uc.CreateProduct(ctx, req)
        
        // Assert
        assert.NoError(t, err)
        assert.Equal(t, expectedProduct.ID, product.ID)
    })
}
```

**Tests business logic:**
- Business rule validation
- UseCase orchestration
- Error handling
- Uses mocked Repository

### Repository Tests (`internal/repository/repository_test.go`)

```go
func TestProductRepository_Create(t *testing.T) {
    t.Run("successful creation", func(t *testing.T) {
        // Arrange
        db := setupTestDB(t)
        defer db.Close()
        repo := NewProductRepository(db)

```

**Tests database layer:**
- SQL operations
- Database connectivity
- Data persistence
- **Uses real database** (no mocks)

### E2E Tests (`tests/e2e_test.go`)

```go
func TestE2E_CreateAndRetrieve(t *testing.T) {
    // Setup complete stack
    database, router := setupE2ETest(t)
    
    // Make actual HTTP request
    req := httptest.NewRequest("POST", "/product", ...)

    // Verify end-to-end flow
    assert.Equal(t, http.StatusOK, w.Code)
}
```

**Tests complete flow:**
- HTTP to database
- Full request-response cycle
- Real dependencies
- **No mocks** (except external APIs if any)

## Mockery Configuration

The `.mockery.yaml` file configures mock generation:

```yaml
quiet: false                    # Show generation output
with-expecter: true            # Generate expecter API
inpackage: true                # Generate in mocks package

packages:
  project-test-primo/internal/usecase:
    interfaces:
      ProductUseCase:
        config:
          dir: "internal/usecase/mocks"

  project-test-primo/internal/repository:
    interfaces:
      ProductRepository:
        config:
          dir: "internal/repository/mocks"
```


## Best Practices

### ✅ Do

- Use mockery to generate mocks for interfaces
- Test each layer independently with appropriate mocks
- Use real database for repository tests
- Test complete flow with E2E tests
- Verify mock expectations are met
- Use specific matchers for precise assertions

### ❌ Don't

- Manually write mock types (use mockery instead)
- Mock the database layer in usecase tests (it's already mocked)
- Skip E2E tests (they catch integration issues)
- Create one mock for all tests (create fresh mocks per test)
- Use overly generic matchers (be specific with expectations)

## Troubleshooting

### "could not import ... mocks" error

Make sure you've generated mocks:

```bash
make mocks
```

Or manually:

```bash
mockery --all --output=internal/usecase/mocks --outpkg=mocks --case=underscore
mockery --output=internal/repository/mocks --outpkg=mocks --case=underscore -r internal/repository
```

### Expectations not matching

Use more specific matchers:

```go
// Too generic
mockUC.EXPECT().
    CreateProduct(mock.Anything, mock.Anything)

// Better - specify what you expect
mockUC.EXPECT().
    CreateProduct(mock.Anything, mock.MatchedBy(func(r *domain.CreateProductRequest) bool {
        return r.Name == "Expected Name"
    }))
```

### Mock not being used

Mockery automatically verifies expectations. If a mock call isn't made:

```go
mockUC.EXPECT().
    CreateProduct(mock.Anything, mock.Anything).
    Once()  // Expects exactly 1 call

// If the function isn't called, the test fails
```
